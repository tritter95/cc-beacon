## Design consequences

1. **Transport:** switch from `type: "http"` to a **synchronous `command` hook running curl that always exits 0**. Headers carry `CC_BEACON_WINDOW`, `CLAUDE_CODE_ENTRYPOINT` and `CLAUDE_PID`. `PostToolUse` can be `async: true`, since it only clears state. On Windows, Git Bash has curl. A PowerShell variant is needed when Git Bash is absent (to be tested on Windows).
2. **Needs-input trigger:** `PermissionRequest`, not `Notification(permission_prompt)`.
   - `tool_name == "AskUserQuestion"` → "Claude has a question", using the question text as the body.
   - Otherwise "Claude needs approval", using `tool_input.description`.
   - When you're away (L2/L3), alert immediately. When you're watching (L0/L1), wait for the 6 s `permission_prompt`, which only arrives if the prompt is still unanswered.
   - Drop the `PreToolUse(AskUserQuestion)` hook.
3. **Clearing needs-input:** denial emits nothing, so clear on `PostToolUse`, `Stop`, `UserPromptSubmit`, focus acknowledgment, or a 6 s `permission_prompt` that never arrives *while you were watching*.
4. **Exact terminal routing:** walk up from `CLAUDE_PID` to a `Terminal.processId`. The active-terminal heuristic is no longer needed.
5. **Panel sessions:** `entrypoint == claude-vscode` → click-to-focus runs `claude-vscode.focus`.
6. **Ignore `SubagentStop`.** It fires ~1 s after every `Stop`.
7. **Declare `untrustedWorkspaces: supported`** in both extensions.
7b. **macOS permission flow:** request permission during onboarding with an explanation first, never at the first real alert. `post` blocks until the user answers the prompt, so never await it on a hot path. Check `status` at activation; when `denied`, show a status-bar warning and a button that deep-links to System Settings. The Info.plist alert-style key isn't honored, so onboarding must tell the user to pick "Persistent".
8. **Corporate Windows** (Todd's Windows machine is corporate-managed):
   - **Showstoppers: ruled out (Todd confirmed Claude Code hooks and custom VS Code extensions are allowed).** For reference, these were: Claude Code managed settings with `allowManagedHooksOnly` or `disableAllHooks` (file `C:\Program Files\ClaudeCode\managed-settings.json`, registry `HKLM`/`HKCU\SOFTWARE\Policies\ClaudeCode`, or server-managed settings, visible via `/status`), and a VS Code extension allow-list policy.
   - **Proxy:** the hook's curl must pass `--noproxy '*'`, because corporate `HTTP_PROXY` would otherwise route the localhost POST through the proxy. Hub↔spoke traffic should use local IPC (named pipe / Unix socket) rather than HTTP, so VS Code's proxy handling in the extension host can't interfere.
   - **No EDR-bait:** never launch PowerShell with `-ExecutionPolicy Bypass` or `-EncodedCommand`, and don't use `Add-Type` P/Invoke. Taskbar flash (which needs `Add-Type`) becomes off-by-default and corporate-unsafe. The worker should run with `-File` (locally built and VSIX-extracted files carry no Mark-of-the-Web, so `RemoteSigned` allows them). Under `AllSigned` or Constrained Language Mode, fall back to in-window alerts and explain why in Diagnose.
   - **Hook runtime:** if there's no Git Bash, Claude Code runs hooks through PowerShell, which takes hundreds of ms to start. Those hooks must be `async: true`, so ordering needs a client timestamp (`[DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds()`).
